JobMatch. — The original project

Designing a workflow to discover vacancies, screen eligibility, research published recruitment contacts, and reduce time wasted on unsuitable job listings.

The problem

01Less manual searching. Better decisions.

Fragmented sources

Openings are scattered across employer sites and job boards with inconsistent formats.

Misleading matches

Junior and remote labels can conceal disqualifying experience, language or geographic requirements.

Difficult outreach

Published contact details need checking before being used for an application.

Proposed workflow

02Five auditable stages

01Collect

Search permitted sources and record where each listing came from.

02Normalise

Standardise fields and remove duplicate postings.

03Check eligibility

Flag location, experience, language and specialist qualification constraints.

04Assess relevance

Compare requirements with documented skills and show uncertainty.

05Verify contacts

Separate actual application emails from general contacts and save the source.

Real-life application

03JobMatch

I built JobMatch to apply the job-screening idea to real vacancies. It lets you filter listings by location and remote work options, including roles you can do from Spain.

Privacy and limitations

05Public demonstration, private data

The original portfolio demonstration uses fictional data. The public tools process CV text locally in the browser; they require no account and do not upload CVs to a server. Scores are simple heuristics, not predictions of hiring outcomes. No emails are sent automatically.

06Next steps

Expand and review vacancy sources, measure screening quality against manual review, and explore source-backed contact verification. Features will be marked implemented only after testing.

New real-life application

07CVFit.

I built CVFit to address the next step in the job search: comparing a CV against a role's requirements before applying.

How it works

Users upload a PDF or TXT file, or paste their CV and the job description. The tool identifies skills, keywords, requirements and relevant evidence, producing a downloadable report with matches and potential gaps.

The analysis uses rules and text matching; it is not a generative AI model or a prediction of hiring outcomes. CV processing takes place in the browser.

Product development

08From a tool to a platform

I designed a modular architecture with shared navigation, a consistent visual identity and independent tools. HTML, CSS and JavaScript power the interface, Python and GitHub Actions support automated vacancy collection, and GitHub Pages hosts the platform.

Future development

Validate results against manually reviewed examples, improve extraction and requirement analysis, and explore new tool categories. The project remains in active development; user outcomes and hiring rates have not yet been measured.
